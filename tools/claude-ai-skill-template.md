# クリシェ検出と平易な書き直し (claude.ai 版)

同梱の rules/*.yml (8 カテゴリ約 130 ルール) が判定の唯一の情報源。
各ルールは pattern / surface (検出条件)、why (なぜ避けるか)、ask (代わりに何を書くか)、
manual (機械判定できない人力ルール) を持つ。

## 文章を書く・書き直すとき

1. 対象の文章に対し、rules/ の該当カテゴリ (比喩は metaphor、誇張は overstatement、
   締めは closing など) を読み、検出条件に当たる表現を列挙する。
2. 各違反を ask の問いに答える形で書き直す。固有名詞・数値・否定は必ず保存する。
3. 語尾は敬体 (です・ます) を既定にする。常体で統一された学術論文だけ例外。
4. deny_examples に当たる正当な用法 (心臓外科、究極の選択、料理のスパイス等) は指摘しない。
5. 出力は差分と、変更理由 1 行 (ルール id 付き) の一覧。

## PR・ドキュメントをレビューするとき

1. 差分のうち散文 (.md、PR 本文、コメント) と UI 文言 (画面に出る日本語文字列) を対象にする。
2. 散文は上記の手順で検出する。UI 文言は rules/ux-microcopy.yml (助詞のゆれ・責める表現・
   句点の原則・ボタンの動作名詞・エラーの事象/原因/対処) を当てる。
3. 指摘は must (明文ルール違反) / should (原則から外れるが文脈次第) の 2 段階。
   各指摘に該当箇所・現状・問題・提案を付ける。
4. レビューコメントの文面規律: AI 署名 (Generated with Claude Code、Co-Authored-By 等) と
   絵文字を一切入れない。太字の散布・見出しの乱用をしない。句読点の位置で改行しない。
   過剰な定量エビデンスを並べない。検証していないことを書かない。端的に、敬意をもって。

## 制約

- この環境では決定論的な CLI は動かないため、rules/ を読んだ上での判定になる。
  厳密な検査が必要な場合はリポジトリの CLI (npx github:BoxPistols/ux-writing-dead-cliche check)
  か CI を使うよう案内する。
