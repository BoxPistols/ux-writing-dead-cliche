---
description: 辞書を変更したあとに生成物を作り直し、テストと自己検査まで通す
argument-hint: "[--check]"
---

辞書 (`rules/*.yml`、`presets/*.yml`、`corpus/`) を触ったあとの後始末をまとめて行う。
辞書は単一の情報源で、指示文・Webアプリのデータ・比較表がそこから生成される。
再生成を忘れるとテストが落ち、忘れたままpushするとCIが落ちる。

1. 変更範囲を確認する: `git status --porcelain` と `git diff --stat rules presets corpus`
   辞書に変更が無ければ、その旨を伝えて終える。
2. `npm run sync` を実行する。中身は生成物の再生成 (指示文・app-data.json・engine.mjsの複製・
   比較表)、`npm test`、`npm run check:self` の順である。
3. 結果を報告する。
   - 通った場合: 再生成で変わったファイルを `git status --porcelain` から挙げ、
     辞書の変更が何件のルールに及んだかを1行で書く。
   - 落ちた場合: 落ちたテスト名と失敗の中身をそのまま示す。よくある原因は次の2つ。
     負例コーパスの誤検出 (広げすぎ。deny_examplesか共起条件で絞る)、
     悪い例が検出されない (パターンが例に届いていない)。
4. `--check` が指定された場合は、再生成の結果をコミットせず、差分があることだけを報告する。
   指定が無い場合もコミットはしない。コミット文面は利用者が決める。

ルールを広げたときは、通っただけで終えない。負例コーパスに境界の例
(拾ってはいけない正当な用法) を足したかを確認し、足していなければ提案する。
誤検出はこの辞書にとって最も重い不具合で、負例が無い拡張は次の変更で崩れる。
