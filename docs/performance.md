# 所要時間とトークン消費

dead-clicheの検出は辞書と正規表現で行い、LLMを呼びません。そのため、CLI・textlint・GitHub Actionでの検査はトークンを消費しません。トークンが関係するのは、Claude Codeプラグインとして使う場合の2か所 (会話に常に入る説明と、フックが返す指摘) と、任意の `--ai` だけです。

計測日は2026-11-27、対象は0.21.0の辞書です。時間はこの計測に使ったMacでの値で、端末の性能によって変わります。

## Claude Codeのフック

ファイルを書いた直後に、変更した行を検査します。

| 場面 | 1回あたりの時間 (中央値) |
|---|---|
| Markdownを書いた (約11,000字の文書) | 0.14〜0.16秒 |
| Markdown以外のファイルを書いた | 約0.11秒 (Node.jsの起動だけで終わる) |
| Markdownに触れないBashコマンド | Node.jsを起動しない |

Node.jsの起動に約0.1秒かかり、検査そのものは0.03〜0.06秒です。

プラグインとグローバル設定の両方にフックを登録している場合でも、同じ編集の検査は1回にまとまります。リポジトリを手元にcloneしてフックから直接呼んでいる端末では、そちらを優先するため、プラグイン側が0.3秒待ちます。プラグインだけの端末では待ちません。

### トークン

- 検出が0件のとき、フックは何も出力しないので、会話にトークンは増えません。
- 検出があると、指摘を最大15件まで返し、Claudeがそれを読んで書き直します。指摘1件は100〜150字ほどです。

## プラグインが会話に常に入れるもの

プラグインを有効にすると、スキル・エージェント・コマンドの名前と説明が、毎回の会話の冒頭に入ります。本文はそのスキルやコマンドを使ったときだけ読み込まれます。

| 種類 | 数 | 常に入る説明の合計 | 使ったときに読み込む本文 |
|---|---|---|---|
| スキル | 4 | 約750字 | 1つあたり1,100〜1,500字 |
| エージェント | 1 | 約80字 | 約600字 |
| コマンド | 7 | 約250字 | 1つあたり500〜1,000字 |

自分の環境での実際のトークン数は、Claude Codeで `/context` を実行すると確かめられます。

## GitHub Action

PRの差分にある文書だけを検査します。

| 項目 | 時間 |
|---|---|
| ジョブ全体 (直近10回) | 8〜14秒 |
| うちActionの実行 (依存の取得と検査) | 約5秒 |

GitHub Actionsは1分単位で課金されるので、1回のPRで1分です。トークンは消費しません。

## `--ai`を付けた場合

`--ai`は既定でオフです。付けたときだけ、機械検出できないmanualルールを型付き判定のAPIで見ます。2026-09-20の計測では、103件の文で入力約30万トークン、31秒、約0.012ドルでした。詳しくは [manual-rules-ai.md](manual-rules-ai.md) にあります。

## 測り直す

フックとCLIの時間は、次のコマンドで測れます。同じ入力を10回流し、中央値と最大を出します。

```bash
node tools/bench-hook.mjs README.md 10
```

GitHub Actionの時間は `gh run list --workflow dead-cliche.yml` で確かめられます。
