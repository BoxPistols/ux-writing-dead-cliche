# 設計ドキュメント

## 目的

AI が日本語文章に持ち込むクリシェ (比喩・誇張・空虚な抽象・構文の型・翻訳調・
締めの型・書式の癖) を検出し、意味を保ったまま平易で事実ベースの文章に直す。
検出だけでなく、「なぜ避けるか」「代わりに何を書くか」を返すことを辞書の責務とする。

## アーキテクチャ

辞書 (rules/*.yml) を単一の情報源にする。理由は 2 つ。

1. スキル (プロンプト) は読むかどうかがモデルの判断に委ねられ、検出の保証がない。
   保証は決定論的なチェッカーが持ち、スキルは書き換えの質を担当する。
2. OSS としての貢献の単位を「YAML の 1 エントリ」にする。UX ライターが
   プロンプトエンジニアリングなしに PR を出せて、テストで回帰を検出できる。

経路は 3 つ: CLI (src/cli.mjs)、textlint ルール (src/textlint-rule.mjs)、
Claude Code プラグイン (skills / commands / agents / hooks)。すべて
src/engine.mjs の check() を通る。

## ルールのカテゴリ

| カテゴリ | 対象 |
| --- | --- |
| metaphor | 羅針盤・心臓部・DNA・架け橋などの比喩 |
| overstatement | にほかなりません・革命的・確信していますなどの誇張断定 |
| empty-abstraction | 本質・真髄・パラダイムシフト・シナジーなどの空虚な抽象 |
| syntax-pattern | 単なるXではなくY・修辞疑問・対句などの構文の型 |
| translationese | することができます・冒頭の私たちはなどの翻訳調 |
| closing | していきましょう・目が離せませんなどの締めの型 |
| formatting | 絵文字見出し・感嘆符連打・太字散布などの書式 |
| ux-microcopy | UI 文言の規範 (助詞のゆれ・責める表現・補助動詞の漢字など) |

## 判定の設計判断

- 誤検出を最小化する。単独では正当な語 (心臓・穴・昇華・確信・道標) は共起条件で
  絞り、deny_examples の通過をテストで強制する。誤検出の報告は negative コーパスに
  再現を足してから直す。
- 機械化できない規範は manual: true で辞書に残す。エンジンはスキップし、
  スキル・レビューの人力チェックリストとして機能する。二重管理 (スキル本文への
  ルール直書き) を禁止する。
- Markdown のコードフェンス・インラインコードは検査しない (オフセット保存の
  空白化で実装)。ルールの説明文書が自分自身に検出される問題の解でもある。
- フック (PostToolUse) は検出時に exit 2 で Claude に書き直しを要求する。
  ツール障害時は exit 0 で握りつぶし、編集を妨げない。

## 文章生成側 (compose)

検出と対になる生成補助として、導入・説明・結論の 3 段落構成の生成コマンドを持つ。
既存のプロンプト集 (自治体 DX のプロンプト実例集など) にある同種のプロンプトとの
違いは 2 点: 装飾の推奨 (キーワードの太字化など) を規律で置き換えたこと、
生成後にチェッカーを通過するまで書き直す品質ゲートを持つこと。外部のプロンプトを
取り込む場合も、このゲートを通せば文体が辞書と揃う。

## 未解決課題

- 副詞の漢字・ひらがな (既に / すでに) は流儀が分かれる (公用文は漢字、JTF は
  ひらがな推奨)。既定ルールにせず、将来スタイル選択式のプリセットで扱う。
- 形態素解析を使っていないため、活用形の網羅は正規表現の記述力に依存する。
  導入するなら kuromoji 系を optional dependency にする。
- 体言止めの連打・三点リスト癖は文書構造の解析が要るため manual に置いている。
  段落単位のヒューリスティックで半自動化できる可能性はある。
- prh.yml 形式へのエクスポート (既存 prh 資産との相互運用)。

## ロードマップ

- GitHub Action (PR の差分に対する自動チェックとコメント)
- VS Code 拡張 (エディタ内での波線表示)
- ルール数の拡充よりも、negative コーパスの拡充を優先する
