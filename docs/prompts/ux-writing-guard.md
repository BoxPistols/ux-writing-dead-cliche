# UI文言規律 (dead-cliche)

画面テキスト (ボタン・エラー・プレースホルダー・空状態) を書くAIへの指示文です。辞書v0.11.0 から自動生成されています。

## 使ってはいけない形

- `## 🚀` → 見出しは内容を表す語だけにする。
- `！！` → 感嘆符を減らし、伝えたい事実を本文に書く。
- `- **重要**` → 太字を外し、重要な項目は先頭に置くか理由を書く。
- `- ✅` → 絵文字を外す。可否は「使える・使えない」等の語で書く。
- `§3` → 参照先の見出し名で書く (「検出の設計方針」の節を参照、のように)。
- `10章で述べ` → 参照先の見出し名で書く。番号は振り直されるが、見出し名は内容と一緒に動く。
- `【完全` → 対象とバージョン・日付など、事実で特定する。
- `e ` → スペースを削る(fixで自動修正できる)。
- `** 重要**` → 太字をやめて平文にするか、正しい記法に直す。そもそも段落中の太字は使わない。
- `保存が失敗しました` → 「〜に失敗しました」に直し、原因か対処を続ける。
- `不正な値` → 事象と対処に置き換える。使える形式・文字を明示する。
- `エラーが発生しました。` → 事象・原因・対処の3要素で組み立てる。少なくとも対処を足す。
- `>OK</` → ボタンは最終的に起きる操作の名詞にする (保存・削除・送信など)。
- `confirm(` → アプリ内の確認ダイアログコンポーネントに置き換える。
- `。」` → 閉じかっこ直前の句点を削る。
- `して下さい` → 「してください」に直す。
- `して頂け` → 「していただく」に直す。
- `が出来ます` → 「できます」に直す。
- `願い致します` → 「いたします」に直す。

## 判断の規律

- 段落内の太字は原則0にする。強調したい内容は文の構成で先頭に置く。
- 強調をやめて語を具体化するか、本当に引用なら出典を書く。
- 「{対象}を入力」「{対象}で検索」の体言止めにする。末尾に記号を付けない。
- タイトルは操作の名詞句 (例、予定の削除)。本文は「{対象}を{操作}します。よろしいですか？」。取り消せない操作には「この操作は元に戻せません。」を必ず入れる。
- 何が起きたか、なぜか、どうすればよいかを分けて書く。エラーコードは末尾に付ける。
- 操作を表す名詞を単体で使う。新規に作る=作成、一覧に足す=追加、フォーム送信=登録、ファイル送付=送信、取得=ダウンロード。迷ったら「このボタンは最終的に何をするか」で選ぶ。
- 初回は「{対象}はまだありません」、絞り込み0件は「該当する{対象}はありません」で書き分ける。
- 完全な文には句点を付け、名詞句で終わるものには付けない。見出し・ボタン・プレースホルダー・テーブルセルは付けない。説明文・通知・エラー・トーストは短文でも付ける。箇条書きはひとまとまり内で統一する。
- フォーム単位でどちらかに統一する。
